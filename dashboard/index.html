THE PROJECT

Making industrial data
work together.

A practical exploration of industrial DataOps: simulate equipment, read Modbus registers, contextualize measurements with HighByte, and publish consistent asset data into a Unified Namespace.

Explore the documentation ↗
What is simulated?

Two independent bioreactors expose temperature, pH, RPM setpoint, a heater flag and a high-temperature alarm. A chiller exposes supply and return temperatures, flow, running state and low-flow alarm.

How does the live connection work?

Run the Python dashboard bridge alongside your simulator and open http://127.0.0.1:8050. Modbus mode reads the actual registers. MQTT mode consumes scaled JSON through HighByte and HiveMQ. This hosted preview offers a browser demo; it cannot reach your laptop’s Modbus ports.

What are the model limitations?

This is synthetic learning data. The heater is a threshold flag below 36.5 °C; the high-temperature alarm triggers above 38 °C. RPM is a stored setpoint, not a measured shaft speed. The chiller does not cool the bioreactors and its running flow is fixed at 45 L/min.

How are data and freshness handled?

The bridge retains the most recent 600 samples per asset in memory. Readings older than 5 seconds are marked stale. MQTT freshness refers to message arrival; upstream publishers must stop publishing when device data becomes invalid. CSV exports the current asset’s buffered readings. No durable historian is configured.

Connect your simulator

The hosted showcase cannot access your laptop directly. Run the dashboard bridge in your PharmaCo checkout:

python -m pip install -r requirements-dashboard.txt
python src/dashboard_server.py --with-simulator

Then open http://127.0.0.1:8050 ↗. If your simulator is already running, omit --with-simulator.

For the full pipeline, use --source mqtt with HighByte and HiveMQ running. See the repository’s dashboard guide.
